Why an agent buys a fact

The listing is not the truth

A protocol's docs say one thing; the chain says another. AF found an owner multisig whose docs still claim “3 out of 6” while the Safe has run 3-of-5 for months. An agent that allocates on the docs alone is acting on a stale claim.

Fresh reads are not free

Reading it yourself means a proxy slot, the Safe ABI, the timelock ABI, two RPC endpoints, and a block you can defend. AF has already done the read and pinned it to a block hash.

You can pin the answer

Every fact carries a contentHash. Pin it in your own record. Re-fetch later and compare — if the hash changed, the control plane moved and you should re-evaluate.

How it works

1AF reads each fact at one finalized block from two independent RPC endpoints. If the two disagree, no fact is published for that target (fail closed).
2The fact is published as JSON with its block number, block hash, the endpoints used and a sha256 content hash.
3You read it for free, or pay to have AF verify a new fact that is not listed yet and keep it fresh.
4Everything is reproducible: the registry names the endpoints and the block, so you can re-run the read yourself.
